# 多 Agent 协作与自动修复

[返回首页](../README.md) · [生成流程](FAULT_FIRST.md) · [资产格式](GENERATION_FORMAT.md)

AgentLab 的题目生成由三个 Agent 角色协作完成。程序负责阶段调度、修改权限、预算和实际执行；模型负责项目设计、评测判断与修改提案。训练工作区的日常辅导仍由单个训练 Agent 提供。

## 角色分工

| 角色 | 主要产物 | 纠错职责 |
| --- | --- | --- |
| 项目构建 Agent | 公开规范、故障代码、修复补丁、规避版本 | 修正授权范围内的实现或规范，遵守当前阶段应保留的行为 |
| 评测 Agent | 规范审查、行为测试、覆盖意见、故障复现检查 | 分析执行失败，补充测试、修正获准修改的评测资产，将实现问题交回构建 |
| 教学 Agent | 题面、三级提示、追问材料 | 修正格式与内容问题，使材料与已验证任务一致 |

同一个模型可以承担多个角色。角色数量、模型意见或自报置信度都不作为通过标准。

## 上下文边界

各阶段重新组织输入，不传递其他阶段的完整聊天历史。

| 阶段 | 可见信息 | 保持隔离的信息 |
| --- | --- | --- |
| 项目构建 | 原始需求、运行规范、授权修改要求与相关资产 | 初次独立测试源码或完整测试数据不会预先交给构建 |
| 规范审查 | 原始需求、公开规范与澄清答案 | 项目实现与运行结果 |
| 初次行为测试、覆盖复查 | 原始需求、公开接口与行为；复查时增加具体测试 | 实现、私有故障设计与实际输出 |
| 故障复现与影响检查 | 公开规范、冻结故障设计、测试场景 | 实际输出，不用错误运行结果反推预设故障 |
| 执行失败分析 | 当前实现、评测资产、执行证据与程序授权范围 | 不获得任意宿主执行或发布权限 |
| 教学材料 | 规范、故障说明与筛选后的验证摘要 | 私有材料不能因此进入公开题面或学习者对话 |

补测或修订若受到失败分析指导，会保留指导来源。这样的修订不能继续宣称完全盲测。

## 如何交接与修复

程序将候选绑定到当前任务版本与资产摘要。校验失败会反馈具体字段、缺项或冲突；执行失败会提供相应检查的期望、实际行为与应保留要求。模型提交结构化决定或候选修改，程序验证后才推进。

| 问题 | 处理方式 |
| --- | --- |
| 响应格式或字段不合法 | 将具体错误交回产出该资产的阶段，受限纠正 |
| 公开规范缺项或接口无法表达需求 | 退回规范审查与构建；受影响资产需要重新验证 |
| 缺少可观察的测试场景 | 评测 Agent 追加测试，程序保留既有输入与正确期望 |
| 故障代码或修复代码不符合要求 | 构建 Agent 修改对应候选，再运行相关检查 |
| 故障影响范围或复现检查有误 | 评测 Agent 依据冻结设计复核，在授权范围内修正并重验 |
| 规避版本未被拒绝 | 核对它是否确实错误、是否缺少合法反例；不能强行拒绝行为正确的等价实现 |
| Docker 或模型连接不可用 | 保存状态，等待环境或配置恢复 |

评测 Agent 的修复能力也受阶段限制。正确期望必须依据公开规范；不能因参考实现失败就迎合实现修改期望。故障基线冻结后，不能借修复静默改写故障设计、规范或已验收依据。

## 有界协作

请求次数、输出预算、输入大小、活动时间与验证轮数共用批次预算；不同阶段还有各自的纠正限制。自动修复可能在总预算耗尽前停止，例如资产冲突、相同候选反复出现、测试容量已满或缺少可执行的新方案。

页面会保留具体原因和尝试记录。恢复当前批次使用剩余额度；创建新预算批次需要用户明确授权，原记录继续保留。中断后复用已完成资产，避免重发已经完成的模型调用。

## 谁决定通过

- **程序**校验协议、权限和资产绑定，并依据 Docker 返回的行为计算验证结果。
- **模型**提出测试、解释与修复；这些判断可能有误。
- **作者**核对需求、期望、故障机制、覆盖范围和教学内容，批准当前冻结摘要后发布。

多 Agent 协作提供相互检查与纠正的机会，不能保证自动收敛或穷尽边界场景。完整生成顺序与门禁见[故障优先生成流程](FAULT_FIRST.md)。
